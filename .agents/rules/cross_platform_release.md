# 크로스 플랫폼 버전 관리 및 배포 규칙 (cross_platform_release)

이 규칙은 Mac과 Windows 두 환경을 동시 지원하는 프로그램의 릴리스 무결성을 유지하고, 플랫폼 간의 교차 버그 발생을 원천 차단하기 위해 적용됩니다.

## 1. 버전 설정 파일 완벽 동기화 (Version Sync)
- 깃허브(GitHub)에 **Push를 하거나 Release Tag를 생성할 때**, 다음 세 가지 버전 설정 파일은 **무조건 동시에, 동일한 버전으로 업데이트**되어야 합니다.
  - `version.json`
  - `version_mac.json`
  - `version_win.json`
- **[CRITICAL] 버전 포맷 엄수:** `version.json` 등의 `version` 필드 값에는 **절대로 'v'나 다른 영문자를 포함해서는 안 됩니다.** 오직 숫자와 온점만 사용해야 합니다. (예: `1.2.187` O / `v1.2.187` X)
  - `auto_updater.py`에서 파이썬 `int()` 변환 시 에러가 발생하여 영구적인 업데이트 실패를 초래하기 때문입니다.
- 한 플랫폼만 업데이트하더라도 버전 정보는 세 곳 모두 일치시켜야 파편화를 막을 수 있습니다.

## 2. 크로스 플랫폼 절대 보호 (Cross-Platform Isolation)
- 현재 작업은 Mac 환경에서 진행하지만, 최종 산출물은 크로스 플랫폼용 소프트웨어입니다.
- **[CRITICAL] 윈도우 버전에서 수정을 할 때 맥 버전이 잘못되거나 절대 영향이 가지 않게 해야 합니다.** 
- 한 플랫폼을 고치느라 다른 플랫폼이 망가지는 핑퐁(Ping-pong) 버그를 방지하기 위해 플랫폼 종속적인 코드(예: 경로 처리, OS API 호출, 윈도우 클립보드, Mac 전용 명령어 등)는 `sys.platform` 또는 `os.name` 등을 통한 **명확하고 철저한 분기 처리(Branching)**로 격리해야 합니다. 한쪽 플랫폼 코드를 수정할 때 다른 쪽에 부작용(Side-effect)이 생긴다면 작업은 전면 무효화됩니다.

## 3. 플랫폼 분기 코드 사전 검증 (Platform Verification)
- 패치나 업그레이드를 수행하기 전, 기존 플랫폼별 대응 코드가 훼손되지 않는지 주의 깊게 점검합니다.
- 특히 파일 경로, 실행 권한, 서브프로세스(subprocess) 명령어 등은 플랫폼별로 다르게 동작하므로, 수정 시 양쪽 OS 모두에 안전한 코드인지(또는 분기가 명확한지) 확인하고 적용합니다.

## 4. 배포 전 무결성 확인
- 버전 업데이트 및 코드 패치가 완료되면, 위 항목들이 충족되었는지 점검한 후 최종적으로 GitHub Push 및 Tagging 작업을 진행합니다.
