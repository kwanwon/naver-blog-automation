# 프로젝트 안정화 및 최종 디버깅 가이드라인 (debug_fix_final)

이 규칙은 프로젝트가 무한 루프나 반복적인 버그 수령 단계에 빠지는 것을 방지하고, 프로젝트를 완벽하게 마무리하기 위해 적용됩니다.

## 1. 버그 수정 전 근본 원인 분석 (RCA)
- 코드를 수정하기 전, 반드시 에러의 **근본 원인(Root Cause)**을 분석하여 설명합니다.
- 해당 수정이 기존의 핵심 기능(로그인, 포스팅, 세션 유지 등)에 미칠 영향도를 평가하여 보고합니다.

## 2. 디버깅 로그 표준화
모든 주요 단계에 상세한 로그를 추가하여 동작 과정을 시각적으로 확인할 수 있게 합니다.
- **포맷**: `[Step N] [모듈명] 동작 설명 (상태: 시도/성공/실패)`
- **대상**: 요소 클릭, 텍스트 입력, 페이지 로딩, iframe 전환, 팝업 처리 등 모든 Selenium 액션 전후.

## 3. 단계별 검증 로직
- 기능을 수정할 때마다 해당 부분만 독립적으로 테스트할 수 있는 **최소 단위의 테스트 방법(Unit Test 또는 스크립트)**을 함께 제시합니다.

## 4. 예외 상황 처리 고도화
- 네이버의 로딩 지연, 셀렉터 변경, 돌발 팝업 등에 대해 '단순 재시도' 대신 다음과 같이 대응합니다.
    - **안전한 종료**: 무한 대기를 방지하고 특정 시간 경과 시 안전하게 루틴을 빠져나옵니다.
    - **원인 기록**: 실패 지점의 HTML 스냅샷이나 구체적인 에러 로그를 남겨 재현 가능하게 합니다.

## 5. 전체 코드 최적화 지침
- 중복 로직을 과감히 통합하고, '최종 안정화 버전'을 목표로 코드를 간결하게 유지합니다.
- 고질적인 버그(예: 이미지 삽입 오류, 줄바꿈 소실 등)를 완전히 제거하는 구조적 해결책을 우선시합니다.

---

## 🛠 실전 디버깅 지침 (자동 적용)

1. **셀렉터(Selector) 우선 검증**: 
   - 요소를 찾지 못할 경우, 코드 수정 전 "네이버 페이지 구조 변경 가능성"을 먼저 점검하고 최신 셀렉터를 제안합니다.
2. **쳇바퀴 방지**: 
   - 동일한 오류가 2회 이상 반복되거나 Selenium으로 해결이 불가능한 수준의 동적 페이지인 경우, 접근 방식을 근본적으로 바꾸거나(예: Playwright 검토) 대체 로직을 제안합니다.
3. **무결성 유지**: 
   - 수정 사항이 다른 플랫폼(밴드, 카페 등)의 공통 모듈에 영향을 주지 않는지 항상 교차 검증합니다.
